# MTIS

Внутренняя система задач и загрузки команды. Локальный MVP на Laravel 13, PHP 8.4, Blade, Alpine.js и SQLite. Все изменения сохраняются на backend; демоданные не являются источником состояния интерфейса.

## Запуск

```sh
composer install
cp .env.example .env
php artisan key:generate
php artisan migrate
npm ci
npm run build
php artisan db:seed --class=DemoSeeder
php artisan serve --host=127.0.0.1 --port=8017
```

Адрес: http://127.0.0.1:8017. В текущем workspace база уже создана, демоданные загружены, frontend собран.

DemoSeeder запускается только в окружениях local и testing, повторный запуск не дублирует данные. Обычный DatabaseSeeder не создает учетных записей.

## Реализовано

- Локальный вход, отключение пользователей, роли и редактируемая матрица разрешений; доступ к задачам ограничен проектами.
- Пользователи, команды, участники проектов, первоначальная и остаточная оценки, сроки и плановые периоды.
- Задачи, подзадачи, приоритеты, типы, поиск, расширенные и сохраненные фильтры, настраиваемые колонки.
- Workflow с отдельной очередью QA, приемом на тестирование, обязательной причиной возврата, повторной проверкой и приемкой.
- Доска задач (Kanban) с серверной проверкой перехода; причины возврата и блокировки обязательны.
- Быстрое назначение из карточки или списка; оценка при начале работы; календарный план вынесен из формы постановки.
- Свой профиль, смена пароля с проверкой текущего, светлая/темная/системная тема.
- Состав команды, руководитель, связанные проекты и переход к загрузке; управление составом своей команды.
- Годовая дорожная карта: крупные работы, ранний старт, длительность, потребность в людях и риски пересечения назначений.
- Комментарии, ответы, упоминания, структурированные результаты проверки, приватные файлы.
- Учет трудозатрат с явным указанием нового остатка; история и аудит.
- Загрузка разработчиков, WIP, превышение емкости, отсутствие оценок, просрочки и блокировки.
- Рабочие дни, индивидуальная емкость, исключения календаря для праздников и отсутствий.
- Обзор, очередь тестирования, отчеты по проектам и времени, CSV-экспорт загрузки.
- Внутренние уведомления и настройки типов уведомлений; планировщик напоминаний о сроках.
- Версионированный API и локально собранный Swagger UI.

## Расчет загрузки

В числителе используется остаток работ в статусах новой задачи, рассмотрения, уточнения, очереди, разработки, возврата, блокировки и отложения. Очередь QA, тестирование, приемка и финальные статусы не занимают производственную емкость разработчика.

Плановые даты задают период распределения остатка. Часы распределяются пропорционально рабочей емкости дней этого периода. При выборе недели учитывается доля, попадающая на эту неделю. Это модель равномерного планирования, а не автоматическое прогнозирование завершения.

Емкость равна сумме рабочих часов выбранного периода. Рабочие дни и недельная емкость задаются у пользователя. Исключение конкретного сотрудника имеет приоритет над общим календарным исключением. Праздники необходимо внести в календарь; региональный календарь автоматически не загружается.

При отсутствии актуального плана или оценки выводятся предупреждения; недостоверный процент скрыт. Незавершенная работа с планом, истекшим до выбранного периода, требует перепланирования и не дает считать сотрудника свободным. Если уже известные часы превышают емкость, перегрузка отмечается даже при неполных данных. При нулевой емкости процент не вычисляется. WIP и число просрочек показываются отдельно. Усилия в других проектах учитываются в общей емкости сотрудника, но названия закрытых для руководителя задач не раскрываются.

Среднее ожидание QA измеряется по рабочему окну 09:00–17:00, понедельник–пятница, в часовом поясе Asia/Almaty. Это базовая метрика MVP; индивидуальные смены QA пока не учитываются.

Расчет ожидания не перебирает часы или весь диапазон дат: полные недели считаются арифметически, отдельно учитываются границы рабочего дня. Историческая очередь на десятки лет проверяется регрессионным тестом без увеличения PHP `max_execution_time`.

## Дорожная карта

Работа дорожной карты отличается от повседневной задачи: это крупный результат с конечным сроком, длительностью в рабочих днях и потребностью в разработчиках на полный день. Плановый старт рассчитывается назад от срока сдачи, включая последний рабочий день. Если срок выпадает на выходной, завершение планируется на предыдущую пятницу. Работы, подготовка которых начинается в предыдущем году, видны в обоих годах.

Система отмечает пропущенный или близкий старт, просрочку, неполный состав и пересечения исполнителей между работами доступных проектов. Разработчик с емкостью 32 ч/неделю дает 0.8 штатной единицы, отключенный пользователь не дает емкости. Состав и сроки изменяет руководитель соответствующего проекта либо администратор; изменения записываются в аудит.

Это базовый годовой план, не автоматический оптимизатор: календарь Пн–Пт по 8 часов, без праздников и отпусков. Текущие задачи и резервы дорожной карты пока считаются отдельно; связи крупных работ с задачами и совмещенный ресурсный прогноз еще не реализованы. Пересечения с закрытыми для пользователя проектами не анализируются. Предупреждения видны в дорожной карте, автоматические напоминания о ее старте пока не отправляются.

DemoSeeder дозаполняет дорожную карту через RoadmapItemSeeder даже в существующей демобазе, не сбрасывает задачи и не перезаписывает измененные планы. Для применения обновления достаточно `php artisan migrate`, `php artisan db:seed --class=DemoSeeder` и `npm run build`.

## API

После входа: http://127.0.0.1:8017/api-docs. Спецификация: `public/openapi.json`.

Основной префикс: `/api/v1`. Используется Laravel session authentication. Изменяющие запросы требуют `X-CSRF-TOKEN`; Swagger UI получает его из страницы автоматически. API не предоставляет обхода проектных и ролевых ограничений.

SQLite использует FTS5 с триггерами для индексации задач, комментариев и имен участников. Для PostgreSQL/MySQL миграция создает полнотекстовые индексы через Laravel. Локальные тесты выполнены на SQLite; смена СУБД требует отдельной проверки и настройки полнотекстового поиска.

Файлы хранятся в `storage/app/private/attachments`, доступны только через авторизованное скачивание. Ограничения: 20 МБ на файл, 100 МБ на задачу; проверяются MIME и расширение. Для PHP/web-сервера необходимо согласовать `upload_max_filesize` и `post_max_size` с этим лимитом. Загруженные файлы не публикуются через storage:link.

## Проверка

```sh
php artisan test --compact
npx playwright install chromium
npx playwright test tests/browser --workers=1 --reporter=list
```

Браузерные тесты требуют запущенный сервер на 8017 и DemoSeeder. Сквозной тест создает собственную задачу и проводит ее до закрытия; записи остаются в истории демобазы.

Серверные тесты используют отдельную SQLite-базу в памяти и проверяют workflow, права, приватные файлы, аудит, индексацию, уведомления и расчет загрузки. Браузерные тесты проверяют формы, все роли, навигацию и адаптацию 390/1440 px. Снимки экрана находятся в `storage/app/qa-*.png`.

Напоминания о сроках:

```sh
php artisan issues:notify-due
php artisan schedule:work
```

В постоянной установке запускается стандартный cron Laravel `schedule:run` каждую минуту. Команда напоминаний запланирована на 09:00 и не дублирует уведомления в течение дня.

## Границы MVP

GitLab/GitHub, CI/CD, SSO, email/Telegram, внешние API-токены, SLA, PWA, шаблоны, автоматизации, произвольные поля и расширенная аналитика остаются вторым этапом. Типы задач и граф workflow уже изменяются через административный API; основной интерфейс настройки ролей и емкости доступен в администрировании.

Полная модель зависимостей между задачами пока не реализована: доступны подзадачи и явная блокировка с причиной. Нет редактирования комментариев, удаления основных сущностей, автоматического обновления экранов через WebSocket и асинхронных отчетов.

Это локальная реализация MVP для проверки сценариев. Промышленное развертывание, нагрузочная проверка целевых 500 мс/3 с, резервное копирование, корпоративная политика хранения аудита и эксплуатационная настройка не выполнялись. В production требуется отдельная база без демонстрационных учетных записей, HTTPS и `APP_DEBUG=false`.
